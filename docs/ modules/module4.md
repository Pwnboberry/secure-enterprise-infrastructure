# Модуль 4. Подключение Ubuntu Server к домену Active Directory

## Цель модуля

Подключить сервер **ubuntu-srv** к домену **company.local**, обеспечив возможность использования доменной аутентификации, централизованного управления пользователями и дальнейшей интеграции файлового сервера Samba с инфраструктурой Active Directory.

---

## Выполненные действия

### Проверка сетевого взаимодействия

Перед вводом сервера в домен была проверена доступность контроллера домена.

Выполнены проверки соединения по IP-адресу и DNS-имени:

```bash
ping 192.168.10.10
ping win-srv.company.local
```
![](https://github.com/Pwnboberry/secure-enterprise-infrastructure/blob/main/screenshots/module_04/пинг.png)

Дополнительно была проверена настройка DNS.

В файле `/etc/resolv.conf` в качестве DNS-сервера указан контроллер домена:

```text
192.168.10.10
```

Корректная работа DNS необходима для функционирования служб Kerberos и Active Directory.

---

### Синхронизация времени

Для корректной работы Kerberos была настроена синхронизация системного времени с контроллером домена.

Установлен и настроен сервис **Chrony**.

В конфигурационный файл был добавлен сервер синхронизации:

```text
server win-srv.company.local iburst
```

![](https://github.com/Pwnboberry/secure-enterprise-infrastructure/blob/main/screenshots/module_04/синхрониз%20время.png)

После внесения изменений служба была перезапущена.

Синхронизация времени является обязательным требованием для успешной аутентификации в домене.

---

### Установка необходимых компонентов

Для интеграции Ubuntu Server с Active Directory были установлены необходимые программные пакеты:

- realmd;
- Samba;
- Winbind;
- libnss-winbind;
- libpam-winbind.

![](https://github.com/Pwnboberry/secure-enterprise-infrastructure/blob/main/screenshots/module_04/Установка%20Samba%20и%20Winbind.png)

Данные компоненты обеспечивают обнаружение домена, взаимодействие с Active Directory и поддержку доменной аутентификации пользователей.

---

### Настройка файла hosts

Для корректного разрешения имени контроллера домена в файл `/etc/hosts` была добавлена запись:

```text
192.168.10.10 win-srv.company.local win-srv
```

Это позволило гарантировать корректное определение контроллера домена независимо от работы DNS-службы.

---

### Ввод сервера в домен

Присоединение сервера к домену было выполнено с использованием утилиты **net ads join**, которая входит в состав Samba.

Была выполнена команда:

```bash
sudo net ads join -U Administrator

```
Во время процедуры использовалась учетная запись администратора домена.

После успешного выполнения операции сервер стал членом домена **company.local**.

![](https://github.com/Pwnboberry/secure-enterprise-infrastructure/blob/main/screenshots/module_04/Ввод%20Ubuntu%20в%20домен%20через%20Samba%20(ads).png)

---

### Настройка Winbind

В процессе интеграции было принято решение использовать **Winbind** вместо **SSSD**, поскольку последний не обеспечивал стабильную работу в данной лабораторной среде.

Для этого была настроена конфигурация Samba и активированы параметры перечисления доменных пользователей и групп.

После настройки были успешно получены списки пользователей и групп Active Directory.

Использование Winbind позволило обеспечить полноценную интеграцию Linux-сервера с инфраструктурой Active Directory.

---

### Настройка PAM

Для обеспечения возможности входа доменных пользователей в систему были настроены модули **PAM**.

В конфигурацию были добавлены компоненты Winbind, благодаря чему сервер начал поддерживать аутентификацию пользователей домена.

После настройки появилась возможность использовать доменные учетные записи при входе в систему.

---

### Проверка работоспособности

После завершения настройки была выполнена проверка корректности интеграции.

Проверены следующие параметры:

- сервер успешно является членом домена **company.local**;
- Winbind отображает доменных пользователей;
- доменная структура доступна для Linux-сервера;
- механизмы Kerberos и PAM работают корректно.

Полученные результаты подтвердили успешное подключение Ubuntu Server к инфраструктуре Active Directory.

![](https://github.com/Pwnboberry/secure-enterprise-infrastructure/blob/main/screenshots/module_04/доказщательства.png)

---

## Используемые технологии

| Технология | Назначение |
|------------|------------|
| Active Directory | Централизованная служба каталогов |
| Kerberos | Доменная аутентификация |
| realmd | Ввод Linux-сервера в домен |
| Winbind | Интеграция Linux с Active Directory |
| Samba | Работа с доменными ресурсами |
| PAM | Авторизация доменных пользователей |
| Chrony | Синхронизация времени |

---

## Результат

В результате выполнения модуля сервер **ubuntu-srv** был успешно интегрирован в доменную инфраструктуру **company.local**.

Выполнены следующие задачи:

- настроено сетевое взаимодействие с контроллером домена;
- обеспечена синхронизация времени;
- установлен необходимый набор компонентов для работы с Active Directory;
- сервер введён в домен;
- настроена аутентификация через Winbind;
- реализована поддержка входа доменных пользователей;
- подтверждено получение пользователей и групп из Active Directory.

Подготовленная конфигурация будет использоваться в следующем модуле при настройке файлового сервера Samba и организации централизованного доступа к общим сетевым ресурсам.
