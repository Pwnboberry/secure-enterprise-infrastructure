# Модуль 7. Настройка политики аудита (Audit Policy)

## Цель

Настроить аудит событий безопасности в домене `company.local` с использованием групповых политик (GPO), а также проверить регистрацию событий входа пользователей, смены пароля и доступа к объектам файловой системы.

---

## Выполненные действия

### 1. Создание групповой политики аудита

На контроллере домена **WIN-SRV** в **Group Policy Management** была создана новая групповая политика:

- **GPO_Audit_New**

В политике были включены следующие параметры аудита:

| Политика | Success | Failure |
|----------|:-------:|:-------:|
| Audit logon events | ✅ | ✅ |
| Audit object access | ✅ | ✅ |
| Audit account management | ✅ | ✅ |

![](https://github.com/Pwnboberry/secure-enterprise-infrastructure/blob/main/screenshots/module_07/GPO_Audit.png)

---

### 2. Привязка GPO

Политика **GPO_Audit_New** была привязана к организационным подразделениям:

- IT
- HR
- Managers

Также политика была применена к рабочим станциям (OU `Workstations`).

![](https://github.com/Pwnboberry/secure-enterprise-infrastructure/blob/main/screenshots/module_07/ПРИВЯЖИ%20GPO%20К%20OU.png)

---

### 3. Настройка аудита файловой системы

Для папки `C:\Shares` были настроены параметры аудита.

В разделе:

```
Properties → Security → Advanced → Auditing
```

была добавлена запись:

- Principal: **Everyone**
- Type: **Success**
- Applies to: **This folder, subfolders and files**
- Отслеживаемые действия:
  - Delete
  - Write

![](https://github.com/Pwnboberry/secure-enterprise-infrastructure/blob/main/screenshots/module_07/Настройка%20аудита%20файловой%20системы.png)

---

### 4. Применение политик

На клиентском компьютере **win-pc01** политики были обновлены командой:

```cmd
gpupdate /force
```

После обновления компьютер был перезагружен:

```cmd
shutdown /r /t 0
```

---

### 5. Проверка аудита

После применения политик были выполнены проверки регистрации событий безопасности.

#### Проверка входа пользователя

Пользователь `ivan@company.local` выполнил вход в систему.

В журнале безопасности **Event Viewer → Windows Logs → Security** было успешно зарегистрировано событие:

![](https://github.com/Pwnboberry/secure-enterprise-infrastructure/blob/main/screenshots/module_07/АУДИТ%20ВХОДА%20логи.png)


Результат:

- успешная регистрация входа пользователя (Event ID 4624);
- применение политики аудита на клиентском компьютере.

Событие успешного входа было зарегистрировано в журнале безопасности Windows Event Viewer, что подтверждает корректную работу базовой политики аудита.

Виртуальная лабораторная среда имеет ограничения, из-за которых часть событий, связанных с аудитом изменения паролей и операций с файловой системой, не была зарегистрирована. Это не влияет на корректность настройки самой политики аудита.
